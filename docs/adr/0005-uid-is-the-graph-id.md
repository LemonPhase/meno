# Identity is the Graph id: `graphs/{uid}`, read off the request

One Graph per user (ADR 0002) means a user id and a Graph id are the same fact, so the signed-in Firebase uid *is* the `graphId` — a request never reaches another reader's subtree, rather than reaching it and being filtered out. Every store function therefore takes `graphId` as a required argument with no default: the demo-user default it replaces would have turned a forgotten argument into a silent read of someone else's Graph, whereas a missing argument is now a compile error. Google sign-in happens in the browser purely to obtain an ID token, which is traded once at `POST /api/auth/session` for an httpOnly session cookie; the cookie was chosen over a bearer token because it rides on every fetch the app already makes, leaving all ~15 call sites untouched and needing no client-side refresh logic. The uid is read from the `Request` object rather than Next's ambient `cookies()`, because the black-box tests call route handlers as plain functions with a hand-built `Request` and there is no request context for `cookies()` to find — the same constraint that makes `MENO_AUTH=scripted` (the cookie taken at face value as the uid, barred in production) the right seam for tests and for interface work, mirroring `MENO_MODEL=scripted`. Firestore Security Rules are not load-bearing here and deny everything: the browser never talks to Firestore, only the Admin SDK behind these route handlers does.
