# Path state is Session-local; the Graph owns only what is known

With concurrent Sessions and cross-session Attach, one Concept can sit on several Sessions' Paths at once — so a single `status`/`order`/`origin` on the Concept can no longer serve (two Sessions would fight over `active`). We split the model: the Graph-level Concept keeps only durable facts (label, summary, `requires`, Unlocked/Skipped, Edits), while each Session owns its Path entries (membership, order, origin, Locked/Active). Unlocking is the one cross-cutting event: when any Session Unlocks a Concept, it leaves every other Path as already known. The alternative — restricting Attach to already-Unlocked Concepts so un-learned Concepts belong to exactly one Path — was rejected because it fails precisely the case Attach exists for: two Topics resting on the same not-yet-learned prerequisite. This supersedes ADR 0002's rider that cross-session deduplication is future work; ADR 0002's core (the Graph as durable per-user container) stands.
