# Deleting a Concept neither cascades nor blocks

When a user deletes a Concept that other Concepts list in `requires`, the dependents simply lose that entry — the deletion is never blocked and never cascades to dependents. The alternatives (block while dependents exist, or cascade-delete the dependents) both protect graph "integrity" at the cost of second-guessing the user. Meno's philosophy is a human-assisted graph: the user curating their own knowledge Graph is trusted, and every Edit is recorded append-only in the audit log anyway, so the agent retains full context of what was removed and can account for it in future Graph updates. Dangling-free `requires` lists keep traversal code trivial; a UX warning before deleting a Concept with dependents is fine, but enforcement is not.
